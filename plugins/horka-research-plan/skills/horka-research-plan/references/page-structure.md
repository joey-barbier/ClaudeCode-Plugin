# Page structure — doc-style, one HTML file

If the project ships a design system or a `doc-style` skill, use it. Otherwise:

## Look

- Cream background `#FAF4F0`, white cards with `2px solid #111` border and a hard `4px 4px 0 #111` shadow, radius 4 px.
- Titles weight 900; body 14–15 px system sans; running text ≤ 70 characters wide.
- Flat chips with meaning: violet `#AE7AFF` = AI / product need, yellow `#FFDB58` = code / entry point, black = human / source, green `#8FE388` = ok / verified, red `#FF6B6B` = limit / false, blue `#87CEEB` = info / partial, grey = neutral / hypothesis, pink `#FF8ACD` = date.
- Light theme only is acceptable if the design system says so; otherwise define tokens on `:root` and dark values under `prefers-color-scheme` and `[data-theme="dark"]`.
- Hash-routed single page: sidebar `nav` with groups, `section.page` per tab, `.page.on` visible, prev / next links at the bottom, default tab `#essentiel`.
- Every tab opens with an "Essentials" box (chip + 3 to 5 sentences in bold where it matters).
- Tables over paragraphs. Each figure cell carries its source link (`<a target="_blank">`), a date, and a status chip.
- Diagrams: inline SVG block diagrams (zones with dashed border and a label tab, boxes with shadow, arrows with `marker-end`), generated by code from a small helper so they stay consistent. Shorten labels rather than shrinking fonts.
- Phone: side gutter `max(16px, env(safe-area-inset-*))`, `min-width: 0` on text containers, tables and diagrams inside `overflow-x: auto`; verify `scrollWidth` ≤ viewport width on every tab at 400 px.

## Tabs

1. **Essentials** — the verdict, a table of the actions (number, link, first datable step, effort, sourced expectation), milestones to respect, a warning box on borrowed ratios.
2. **Where we really are** — KPIs (point zero), the three-state table (prod / develop / PRs), what the web says when you search the name, what already exists and is reused.
3. **Big picture** — one diagram: sources → entry points → what converts → measurement; the funnel today vs a sourced benchmark.
4. **90 days** — sequence diagram and a table per fortnight with effort and dependencies; two dated decision gates.
5. **One tab per action** — meta chips (effort, result delay, cost, product need, when); "Where we are / Why we do it / What we expect back" in three columns; diagram; steps table; expectations table (indicator, today, benchmark, source + status); a rule or risk box.
6. **What we do not do** — every dropped action with its reason and the condition under which it comes back.
7. **Rules and risks** — brand risks and the rule for each; fragile hypotheses; what reviewers corrected in the figures.
8. **Real demand** — method, the topics table, consequences for the plan, what could not be measured.
9. **Personas** — reaction per action with effect chips (try / neutral / flee), what is missing before paying, rules imposed, sources.
10. **Reference figures** — every number cited, one row each, with source, date, status.
11. **Product needs and tasks to hand over** — needs (for whom, size), tasks with dates, and the explicit list of what the plan does not create itself.
12. **Method and limits** — the agent team as a flow, what was done per step, honest limits (blocked sites, unavailable local skills, no volume tool).

## Build

Generate the page from code (Python or Node): sections as strings, a `tbl(head, rows)` helper, `src(url, label, note)` and `chip(kind, text)` helpers, diagrams from a tiny SVG helper. Keep the sources in a scratch folder; publish only the HTML. One deliverable: no Markdown copy.
